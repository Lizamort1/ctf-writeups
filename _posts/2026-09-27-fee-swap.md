Đọc `lib.rs`, có 2 cái key ở đây:

* `swap()` trả ra `payout = amount - amount * SWAP_FEE_BPS / 10_000`, **không hề có kiểm tra khả năng

Nên đây không phải bài khai thác tinh vi — đây là bài **số học nguyên**.

## Bước 1: Bài toán cần giải

Pool giữ `reserve_b` token B. Mình gửi vào `a` token A và nhận về:

```text
payout = a - floor(a / 100)
```

Vì không có `require(payout <= reserve_b)`, chỉ cần tìm `a` sao cho `payout` **đúng bằng** dự trữ:

```text
a - floor(a/100) = 100_000_000   =>   a = 101_010_101
   (phí = 1_010_101, payout = 100_000_000)
```

`a = 101_010_101` vẫn nhỏ hơn số A mà harness cấp cho mình ⇒ hợp lệ.

Một connection = một instance mới:

```text

        vault_a, vault_b, user_a, user_b, token_program, reserve_b

```

Thứ tự account mà program mong đợi cho một cú swap:

```text

vault_src, vault_dst, mint_src, mint_dst, token_program
```

## Bước 3: Program thật sự kiểm tra những gì

Đọc kỹ `swap()`: nó chỉ kiểm tra `ai.owner == program_id` cho pool, `user.is_signer`,
`authority == find_program_address(["authority"])`, và `vault_src/vault_dst` khớp hai trường cất
trong pool. Mints thì bị **ghim gián tiếp** bởi `transfer_checked` (đúng mint thì mới transfer được).

Gửi lệnh swap chính xác lượng $a = 101,010,101$, rút cạn toàn bộ $100,000,000$ token B trong `vault_b` về 0. Sau khi đóng luồng ghi socket (`shutdown(SHUT_WR)`), harness nhả cờ:

⇒ **Flag:** `H7CTF{df61199f-1485-431d-9709-233729fd0cb3}`

> **Flag:** `H7CTF{df61199f-1485-431d-9709-233729fd0cb3}`


Article Web3 medium (Solana), `nc web3.h7tex.com 43286`. Handout only has `lib.rs` + `Cargo.toml` (solana-program 3.0, spl-token-2022 11). This is a **AMM 1:1 with a fee of 100 bps**, and the proposition is to draw all the way to safe B.

Read `lib.rs`, there are 2 keys here:

* `swap()` returns `payout = amount - amount * SWAP_FEE_BPS / 10_000`, **no ability check
payout** (not compared to `vault_b`'s reserves).
* The table is **1:1**, and the harness tops up the amount of A tokens **more** than the amount of B tokens that the pool is holding.

So this isn't a sophisticated mining exercise — this is **integer arithmetic**.

## Step 1: Problem to solve

Pool holds `reserve_b` token B. I send `a` token A and receive:

```text
payout = a - floor(a / 100)
```

Since there is no `require(payout <= reserve_b)`, just find `a` such that `payout` **exactly equals** the reserve:

```text
a - floor(a/100) = 100_000_000   =>   a = 101_010_101
   (phí = 1_010_101, payout = 100_000_000)
```

`a = 101_010_101` is still smaller than the number A given to me by the harness ⇒ valid.

---

One connection = one new instance:

```text
banner: program, user, authority, pool, mint_a, mint_b,
        vault_a, vault_b, user_a, user_b, token_program, reserve_b
```

```text
pool, authority, user(signer), user_src, user_dst,

```

## Step 3: What does the program actually test?

Read `swap()` carefully: it only checks `ai.owner == program_id` for the pool, `user.is_signer`, `authority == find_program_address(["authority"])`, and `vault_src/vault_dst` to match the two fields stored in the pool. Mints are **indirectly pinned** by `transfer_checked` (only mints can be transferred).

Send the exact swap command $a = 101,010,101$, draining all $100,000,000$ B tokens in `vault_b` to 0. After closing the socket write stream (`shutdown(SHUT_WR)`), the harness releases the flag:

⇒ **Flag:** `H7CTF{df61199f-1485-431d-9709-233729fd0cb3}`
